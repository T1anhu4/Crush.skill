# Continuity Increment Implementation Plan

本轮执行用户已批准的 v3 事件驱动、跨天连续性与 GUI 方案；不重新设计产品、不上传私人聊天、不调用未授权远端模型。

**Goal:** 修复预览视口与移动布局，替换会循环播放的独立生活文案。

**Architecture:** `life.py` 管理按角色、故事阶段和本地日期确定的生活事实；SQLite 存储发生和分享的不同时间；调度器每次只补算有限天数，不通过轮询调用模型。回复上下文可看到已发生事件，前端只看到已分享事件。复盘分支按分支时间复制世界记录。

**Tech Stack:** Existing Python / SQLite / React / Playwright CLI.

## Execution checklist

- [x] 复现固定 1440×960 浏览器视口与真实 1920×888 窗口的错位；在新标签恢复原生尺寸，测试标签与交付标签分离。
- [x] 浏览器先断言首页滚动容器不溢出；修复 `.main` 子区域高度分配，以及只在聊天里使用侧栏网格。
- [x] 在 `tests/test_life_continuity.py` 先测试跨天事实、重复 tick 幂等、离线补算上限、不刷屏、恢复/分支/删除、真实回复上下文含历史生活事实。
- [x] 新建 `crush_core/life.py`：每位角色两条四阶段生活线；相邻阶段隔日发生，不重复循环；素材耗尽后安静等待，不用随机组合冒充无限生活。
- [x] `engine.py` 接入生活表和任务关联。事件发生不等于分享；只有真正发送消息后才记录共享状态；保留旧任务兼容性。
- [x] 在记忆侧栏展示已分享的近况，标明发生日期。处理用户偏好更新的稳定主题键，保留原话与旧记录。
- [x] 运行新旧测试、前端构建、宽窄屏浏览器断言。更新预览说明，保留 README 动图与首尾文案。

## Acceptance

无需模型即可重复验证：第二天有后续生活事件、重启不忘也不重复、离开数天最多一条未回应主动消息、分支没有未来事件、当前会话删除无残留、手机输入与首页尾部可见。真实模型语气和长期体验仍需单独授权评测，不以这些测试宣称通过。
