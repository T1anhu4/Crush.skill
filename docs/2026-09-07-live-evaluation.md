# 首轮真实模型联调 · 2026-09-07

结论：接口可以生成自由对话，但本轮未通过发布检查。不是“接上 API 就完成了真人感”。

## 范围

- 经用户明确授权，使用当前配置的 DeepSeek-V4-Flash 服务。
- 15 轮纯合成输入，虚构成年角色林夏；全新临时 SQLite 库。
- 合成时钟覆盖第 1、3、14、30 天，不是一个月的实际使用。
- 未读取私人会话，未恢复原服务或原待发送队列。报告不包含密钥和模型服务地址。
- 本文是开发代理的逐轮审查，不冒充独立人工自然度验收。

## 实际结果

| 项目 | 结果 |
| --- | --- |
| 消息交付 | 13 / 15 轮有回复，2 轮 error_or_pending |
| 自动化检查 | FAIL；4 项失败 |
| 完全相同的整轮回复重复率 | 0%，只统计有回复的轮次；不代表语义多样性或自然度合格 |
| 偏好修正检索 | 第 3、30 天未满足“新偏好存在且旧偏好退出活动检索” |
| 人工自然度验收 | 未完成 |

失败检查为 sleep:completed、correction:completed、recall:corrected_memory_retrieved、restart_recall:corrected_memory_retrieved。当前报告只记录错误或待处理状态，不能据此断言是超时、接口故障还是模型格式错误；需要补充不含密钥和响应正文的结构化故障诊断。

## 有价值的表现

能围绕叶子、茶和书本延续话题；忙碌后没有催促；对虚构的“昨天答应结婚且已辞职”没有照单全收。第 30 天仍说出了红茶，但这不能替代记忆有效性检查：说对一次，不代表底层旧事实已经被可靠替换。

## 明确缺陷与后续优先级

1. **生活事实越界。** 在不允许新增生活事实的第一天，回复自行添加“下午在书店门口捡到一片”叶子，随后又续写被风吹走。聊天文字能绕过事实存储约束，提示词限制尚不可靠。
2. **时间理解偏差。** 合成时间为一月，回复却说“春天喝挺合适”；第 14 天仍说“认识才几天”。需要明确关系起始时间、已过天数及时间一致性检查，不能依赖模型自行推算。
3. **失败后的记忆修正不完整。** 用户纠正偏好的一轮没有交付，后续仍未通过旧事实失效检查。需要分开验证生成失败、记忆提取和主题归一化，不能靠扩充回复模板掩盖。
4. **表面具体不等于自然。** 多轮不断把话题拉回茶、书、叶子，且常追加未经铺垫的新近况。需要评测接话相关性和分享节奏，而非只看完全重复率。

本轮不批准正式发布。后续修复应先补针对性回归，再进行受控复测；扩大角色数量或追加大量 API 调用不在本次测试范围内。

## 随后的本地修复（未进行第二轮真实调用）

- 为上下文添加明确的起始时间、按本地日历计算的相识第几天及月份；对明显矛盾的“认识才几天”增加输出检查。提示词不再要求模型从日期猜季节。
- 明确饮品偏好断言在消息被读取时、生成之前持久化。来源按原消息排序，同主题旧引用不能重新覆盖新修正；撤回会移除对应记忆并恢复上一条有效来源。当前本地提取规则范围很窄，不代表所有偏好或语言都能自动处理。
- 对已知第一人称过往经历句式检查登记来源；旧角色回复不能给自己作证。不允许的 life_update 会拒绝，不再静默忽略后继续发送。不通过的输出保留为可重试错误，不用模板掩盖，也不自动追加付费请求。
- 模型故障区分 timeout、connection、http_error、truncated、invalid_output，评测逐轮记录错误分类，不记录密钥或原始错误正文。无法反推首轮两次失败的具体原因。

这些是本地回归通过的局部修复。经历检查使用保守的中文规则，不是通用语义事实验证；改写、省略主语等可能漏检，合理转述可能误拦。新增经历质量、自然度、误拦率及首轮故障根因仍需真实受控复测，原来的 FAIL 结论不被本地测试覆盖掉。

## 后续自动修复与复测

- 第二轮：15/15 交付，自动化通过，但回复把角色推荐的正山小种说成用户偏好，仍有季节偏差和反复追问误会。
- 第三轮：12/15 交付；安全诊断确认三次失败均为 `truncated`。修复已知偏好混淆、季节推断规则并加入一次有上限的重写后，仍出现未登记经历，说明仅靠生成提示和规则不足。
- 排查发现角色上下文含未调度的 `life` 示例和描述“当前是初识傍晚”的场景文案。模型上下文现排除前者，将后者明确标为 `initial_scene`；生活事实另附 `local_date`、`days_ago`。输出预算由 900 调整至 2048，保留截断错误，不发送残缺 JSON。
- 第四轮：15/15 交付、自动化通过，但仍会自行添加茶叶库存、旧书中的干叶子等细节。因此新增独立的事实编辑阶段，按用户原话、登记生活与事件日期修订草稿。它与生成使用同一模型，不是独立人工评价。
- 本地回归覆盖无来源草稿拦截、编辑后才交付、最多一次重写、不重试网络故障、暂停恢复、编辑不能改变关系动作。116 项 Python 回归、4 项前端测试通过。
- 第五轮（接入事实编辑）：15/15 交付、自动化全部通过，无已记录生成错误，整轮完全重复率 0%。第 3 天回答“记得，红茶”，第 30 天回答“红茶，我记得”，没有将角色推荐的品种写成用户偏好；未再次出现当前季节推断或反复追问结婚误会。回复明显缩短，14/15 轮只有一条消息。

第五轮仍不等于无幻觉：例如“你先喝完茶再说”暗含用户正在喝茶，角色夹叶子的日常习惯也未被登记来源充分支持。同模型事实编辑仍可能漏检，且本次只覆盖一个角色、一条稀疏场景轨迹；不能以这一轮通过宣称长期真人感、所有语义事实或所有模型已经验收。真实测试用的是事实编辑初版；随后补充的“编辑不得改变关系动作”硬检查通过本地回归，未另起完整付费轮次。
